# October 7 final-review transport failure

Investigated against master `3cd4cc445691539cdbcd3d53ed8e97c0030ea3a8`
and live Azure read-only evidence on October 7, 2026. No model request,
job restart, resource/configuration change, or publication was performed.

## Finding and limit

The third/final review failed in the model HTTP transport path. Azure Monitor
records two `gpt-5-mini` requests with status 200 and one `grok-4.6` request
with status 499 in the execution window. This strongly correlates the failure
with the Grok review, although aggregate metrics have no per-request ID tying
them conclusively to this job. Status 499 is commonly used for a client-closed
request; it does not identify why the connection closed.

A client timeout is plausible, but **not verified**. The old catch block
discarded the exception type, request phase, and elapsed time. Its message also
covers DNS/TLS/socket errors, interrupted HTTP reads, and ValueError. There is
no evidence supporting an authentication rejection or nonexistent deployment.
The persisted manuscript proves generation and voice editing completed.

The exact remaining blocker is missing request-level evidence: the container
log repeats only the sanitized generic error, the state has no request ID or
timing, and the Foundry account currently has no diagnostic settings
(`diagnosticSettings.value` is empty). Resource-level metrics cannot distinguish
a client deadline from a connection interruption or upstream cancellation.
Do not treat the absence of configured diagnostics today as proof of their
historical configuration.

## Small repository correction

Keep the existing transport failure prefix, but append a fixed allowlisted
category, `open` versus `read` phase, call ordinal, monotonic elapsed seconds,
and the configured socket timeout. Classify wrapped urllib errors by type,
never by raw exception text. `open` includes DNS/connect/TLS/send/response
headers; it does not pinpoint which of those phases timed out. Preserve the
separate identity-request label and 10-second identity timeout.

This corrects the proven loss of diagnostics; it is **not a claimed fix for
the Azure outage**. Keep HTTP status reporting, credential sanitization, daily
reservation, three-call cap, timeout values, no retries, exact-content review,
and all compliance holds unchanged. October 7's ledger, draft, and queue are
untouched. A subsequent naturally scheduled failure, after this patch is
reviewed and merged, can retain the missing category without an extra call.

Validation: `python3 -m unittest discover -s daily-engine -p 'test_*.py' -v`
passed all 107 tests offline. New coverage includes direct/wrapped transport
errors, sanitized timing, body-read timeout, identity isolation, and a real
AzureWriter with mocked transport failing on call three. That regression
verifies exact review bytes, retained usage, manuscript hold, no repeat daily
attempt, and rejection of a fourth call.
